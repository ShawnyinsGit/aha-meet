# S0 黑客松方案：AhaStation 概念验证 Demo（3 天 / 4 人）

> **版本**：草案 v1　**日期**：2026-07-21　**状态**：待 grill 评审
> **上游文档**：`docs/plan-ahastation-rk3588-overall.md`（S0 行，D8）
> **核心原则**：**验证概念，不验证可行性**。硬件 suspend、散热、5G、ODM 全部出局——这些是 S1/S2 的事。黑客松只回答一个问题：

---

## 1. 要验证的命题（Hypothesis）

> **「语音驱动的 AI 编程 agent 会话」作为一种交互形态是成立的：用户对着一个 ARM Linux 小设备说话，agent 就在远端写代码、改代码、汇报结果，这个过程自然、可靠、有价值，值得为它做一台专用硬件。**

拆解为 3 个可判定的子命题：

| # | 子命题 | 判定方式 |
|---|---|---|
| H1 | **语音即指挥**：免动手（按住说话/自然打断）驱动 agent 完成真实编码任务，体验显著优于打字 | Demo 现场盲操作完成 ≥3 个真实编码任务 |
| H2 | **会话式协作**：「会议」式多轮交互（提问、打断、追问、批准/驳回）比单轮 prompt 更自然地控制 agent | 演示一次包含打断 + 驳回 + 改方向的完整任务 |
| H3 | **ARM 小设备能承载这个交互壳**：在 RDK X5（8 核 ARM SoC，远低于 RK3588）上 Electron/网页 UI + 音频链路 + agent CLI 跑得动、不卡 | Demo 全程在 RDK X5 本机运行，帧率/延迟可接受 |

**不验证**：suspend-resume、功耗、散热、5G 模组、Panfrost GPU 加速、whisper NEON 吞吐、设备树适配——全部不在黑客松范围，写进"出局清单"防止 scope 蔓延。

## 2. Demo 定义（终点画面）

**最终 5 分钟演示脚本**（这是黑客松唯一交付物，一切工作倒排自它）：

1. **开场**（30s）：RDK X5 接小屏/大屏，AhaMeet UI 全屏运行，一句话介绍命题。
2. **任务 1 · 口袋模式模拟**（1.5min）：按住（模拟）PTT 键说需求：「给这个 CLI 工具加一个 --verbose 参数」→ 云端 ASR → agent（Claude Code）在本机仓库改码 → TTS 汇报「改完了，3 处改动」→ 屏幕显示 diff。
3. **任务 2 · 打断与驳回**（1.5min）：agent 改到一半，说「不对，别动那个文件，换个方案」→ agent 停下、回滚、换方向 → 展示"打断"按钮和驳回交互。
4. **任务 3 · 真任务**（1.5min）：现场从观众抽一个小需求（提前准备 3 个兜底题），语音驱动 agent 完成并跑通测试。
5. **收尾**（30s）：亮出「下一步」——S1 CX10A 真机验证清单。

**降级预案**（每一层都要有，黑客松铁律）：
- L1 完整：实时语音全链路。
- L2：ASR 实时但 TTS 降级为文字气泡（§3.4 本机 TTS 零语音问题已知）。
- L3：语音降级为快捷键触发预录语音 / 现场打字，agent 交互链路必须全真。
- L4（地板）：录屏视频 + 现场口述，**必须有真跑过的证据**。

## 3. 范围

### IN（做）
- RDK X5 上跑通 Ubuntu/Debian + AhaMeet 的**最薄切片**：
  - 语音输入（按住 PTT 网页按钮即可，GPIO 侧键出局）→ 云端 ASR（用现成的、最快接的，供应商选型 Q5 不在此决策）
  - agent CLI（**只接 1 个：Claude Code**，官方 aarch64 二进制，证据最足）单会话跑通「说 → 改码 → 汇报」
  - 打断（barge-in 简化为"打断按钮/按键发新指令中止当前轮"）
  - TTS：云端 TTS 主路径，失败则文字气泡（L2 降级是预期路径之一）
  - diff 展示：agent 改完后 UI 显示改动摘要（终端输出 + 简化 diff 视图）
- 一个预装好的 demo 仓库（含故意留的简单任务：TODO、缺参数、失败的测试）
- 演示脚本 + 降级预案演练 1 次

### OUT（出局清单，谁提砍谁）
- GPIO 侧键、PTT 硬件键（用屏幕按钮/键盘代替）
- whisper.cpp 本地 ASR、离线兜底（黑客松全程联网）
- 5G 模组（用 WiFi/有线）
- 多 agent 编排、多会话（单 agent 单会话）
- 陪伴屏/吉祥物（Phase 8，无）
- 外接显示器自动切换（手动切）
- 桌面模式多窗口（UI 全屏单窗口即可）
- OTA、刷机、设备树、内核（RDK X5 用官方镜像开箱即用，禁止刷机折腾超 2 小时）
- 性能优化、美观打磨（能跑 > 好看）
- RK3588 相关一切（CX10A、Firefly 均不拆封）

## 4. 人员与分工（4 人）

| 角色 | 人 | 职责 | 关键交付 |
|---|---|---|---|
| A · 系统集成 | 1 人 | RDK X5 系统起板、Node/Electron 环境、agent CLI 安装跑通、demo 仓库准备 | Day1 晚前「在 X5 上 CLI 手动能跑 agent」 |
| B · 语音链路 | 1 人 | 云端 ASR 接入（浏览器 getUserMedia → WebSocket/REST）、TTS 接入、打断逻辑 | Day2 中午前「说话→文字→agent」管道通 |
| C · UI/交互 | 1 人 | AhaMeet 最薄 UI：PTT 按钮、会话气泡、diff 摘要视图、打断/驳回按钮、降级状态提示 | Day2 晚前 UI 全流程可走 |
| D · 演示 + 补位 | 1 人 | Demo 脚本、demo 仓库任务设计、降级预案、全程集成测试、最后彩排；兼 Product Owner 守门砍 scope | Day3 下午彩排通过 |

**规则**：D 有 scope 否决权；任何人想加范围外功能，D 引用「出局清单」驳回。A/B/C 卡住超过 2 小时必须升级，全组当场决定降级。

## 5. 三日排期

### Day 1（打通管道，UI 可以丑）
- 上午：A 起板 + 装环境（Node、依赖、Claude Code aarch64）；B 选定云端 ASR/TTS 供应商并拿到 key、写最小调用脚本；C 搭 UI 骨架（静态 mock 数据）；D 写好 demo 脚本 + demo 仓库（含 3 个任务）。
- 下午：A 跑通「CLI 手动驱动 agent 改 demo 仓库」；B 跑通「浏览器录音→ASR→文字」；C UI 能显示假会话。
- **Day1 出口标准（Gate 1）**：`语音→文字` 和 `文字→agent→diff` 两条半管道各自单独打通（可以不连着）。未过 → 当晚砍 TTS，走 L2。

### Day 2（连起来，端到端）
- 上午：B+A 把 ASR 输出接进 agent 会话；打断逻辑（中止当前轮）；C UI 接真数据。
- 下午：**第一次端到端**「按住说话 → agent 改码 → 汇报 → 显示 diff」；修最大的 3 个卡点；D 验证降级路径（断 TTS、断 ASR 各演一次）。
- **Day2 出口标准（Gate 2）**：端到端走通 ≥2 次（允许卡顿、允许手动救场）。未过 → Demo 定为 L3（语音触发预录+打字），保 agent 链路全真。

### Day 3（加固 + 彩排）
- 上午：冻结代码；只修演示路径上的致命 bug；准备兜底视频录屏（L4）。
- 下午：彩排 ≥2 次（含一次故意走降级路径）；检查网络备份（手机热点）；最终演示。
- **交付**：5 分钟演示 + 一页「概念验证结论」（H1/H2/H3 各自成立/存疑/证伪 + 证据）。

## 6. 成功标准（判定"概念成立"的尺子）

| 级别 | 标准 |
|---|---|
| **成功** | 现场 L1/L2 完成演示脚本任务 1+2，任务 3 完成或部分完成；H1/H2 判定成立；录屏可作为 S1/S2 与 ODM/投资人沟通素材 |
| **可接受** | L3 完成演示，语音链路存疑但「语音指挥 agent」交互价值在彩排中已被团队确认（H1 部分成立） |
| **证伪也是成果** | 若端到端体验证明「语音驱动编程」并不自然/无价值，明确写出证伪证据——黑客松的目的就是便宜地知道 |

## 7. 风险与对策（黑客松内）

| # | 风险 | 对策 |
|---|---|---|
| H-R1 | RDK X5 起板/环境装不上（arm64 依赖、Chromium 问题） | 2 小时止损线；B 方案：AhaMeet 以 **web 版跑在 X5 的 Chromium**（或干脆浏览器全屏），Electron 非必需 |
| H-R2 | 云端 ASR 中文流式接入耗时超预期 | Day1 上午必须选定并调通 hello-world；超时下换非流式（按住说完整句再识别），牺牲打断换进度 |
| H-R3 | Claude Code 在 X5 上跑不动/太慢 | 降级：agent 跑在**局域网内一台 x86 开发机**上，X5 只做语音+UI 终端（注：这恰恰就是产品形态的分布式变体，不影响 H1/H2 判定，H3 降级为"UI 壳可承载"） |
| H-R4 | 现场网络不稳 | 手机热点备份；L3/L4 预案 |
| H-R5 | 4 人 3 天 scope 蔓延（最大风险） | D 持出局清单守门；每日站会 15 分钟对 Gate |
